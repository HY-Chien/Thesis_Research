
\chapter{Experiments}
\label{ch:exp}

This chapter evaluates the final SEEK system under the same honest wiki-21M retrieval protocol used for the DeepRAG comparison. The experiment narrative follows six questions. First, how does SEEK compare with DeepRAG overall? Second, does decomposition actually improve retrieval? Third, is retrieval still necessary after decomposition? Fourth, what role does the entropy gate play? Fifth, why should original questions and decomposed sub-questions use different retrieval settings? Finally, how much headroom remains in the direct-vs-decompose routing decision?

\section{Experimental Setup}
\label{sec:exp-setup}

\subsection{Datasets}

We evaluate on HotpotQA, 2WikiMultihopQA, MuSiQue, and PopQA. HotpotQA, 2WikiMultihopQA, and MuSiQue test multi-hop reasoning, while PopQA tests single-hop factual recall and exposes over-decomposition on simple entity-centric questions. To align with DeepRAG~\cite{deeprag}, all headline results use the first 1{,}000 questions of each development set without shuffling.

\subsection{Retrieval Corpus}

The main comparison uses the honest open-domain corpus: the shared Elasticsearch \texttt{wiki} index over \texttt{psgs\_w100}, containing approximately 21M Wikipedia passages. We use BM25 with top-$k=8$ for HotpotQA, 2WikiMultihopQA, and MuSiQue, and top-$k=3$ for PopQA. SEEK applies a path-aware title policy: the direct path retrieves with the original question over paragraph text only, while the decomposition path retrieves short sub-question queries over title and paragraph text. This policy is dataset-agnostic because it depends only on query type.

The final system further uses \emph{original-question evidence union}. For each decomposed sub-question, the evidence context is the union of passages retrieved by the sub-question and passages retrieved by the original question. This preserves the global context that can be lost when a long question is decomposed into short sub-questions.

\subsection{Metrics and Baselines}

We report SQuAD-style exact match (EM) and token-level F1 after standard normalisation. When a dataset provides aliases, the maximum score over aliases is used. The main external baseline is DeepRAG~\cite{deeprag}, which learns a sub-question-level retrieval policy through binary tree-search rollouts, SFT, and DPO-style Chain of Calibration. Internal comparisons include the path-aware baseline, the original-question evidence union ablation, and the final SEEK system with type-aware verifier replay.

\subsection{Implementation Details}

All SEEK results use Llama-3-8B-Instruct with the 12K three-source LoRA decomposer trained on MuSiQue, 2WikiMultihopQA, and PopQA. The decomposition path uses Mode C, maximum token entropy threshold $\tau=0.3$, and synthesis with the LoRA adapter disabled. The final verifier uses the original v2 confidence signals plus a conservative type-aware fallback. This fallback changes only the final choice between the direct and decomposed candidates; it does not rerun generation and does not train an additional model.

\textbf{Finding 1: SEEK improves the four-dataset average over DeepRAG.} The final SEEK system reaches 40.52 EM and 47.61 F1, compared with DeepRAG's 38.45 EM and 45.75 F1. The average gain is therefore +2.07 EM and +1.86 F1.

\textbf{Finding 2: SEEK wins on 2Wiki, MuSiQue, and PopQA.} On 2Wiki, SEEK improves from DeepRAG's 48.10 EM to 50.00 EM. On MuSiQue, it improves from 22.50 to 24.70 EM. The largest gain is on PopQA, where SEEK reaches 51.90 EM compared with DeepRAG's 42.50.

\textbf{Finding 3: HotpotQA remains the only dataset below DeepRAG.} SEEK improves HotpotQA from the path-aware baseline of 31.80 EM to 35.50 EM, but it still trails DeepRAG's 40.70 EM. This makes HotpotQA the main remaining limitation and motivates the analysis in Sections~\ref{sec:path-distribution}--\ref{sec:oracle-analysis}.

\section{Entropy as a Confidence Signal}
\label{sec:entropy-analysis}

Entropy remains useful, but it should not be overstated. Across pooled examples, higher answer entropy is associated with a higher error rate, with Spearman correlation around +0.326. This supports max entropy as a sub-question-level retrieval gate. However, low entropy does not guarantee correctness: the model can be confidently wrong. This is why SEEK uses entropy as one confidence signal inside a dual-path system rather than as a single global router.

\section{Summary}

The final experiments support four conclusions:

\begin{itemize}
    \item \textbf{SEEK outperforms DeepRAG on average under honest wiki-21M.} It wins on 2Wiki, MuSiQue, and PopQA, while HotpotQA remains the only dataset below DeepRAG.
    \item \textbf{Decomposition improves retrieval, but retrieval remains necessary.} Answer-containing recall improves strongly on multi-hop datasets, and never-retrieve ablations lose 9.3 to 27.3 EM.
    \item \textbf{Entropy is an efficiency signal, not a correctness guarantee.} The gate nearly matches always-retrieve accuracy while saving some retrieval, but low entropy can still be wrong.
    \item \textbf{Direct and decomposition paths are complementary.} Oracle gaps of 3.8 to 6.1 EM show that direct-vs-decompose routing remains an important source of future improvement.
\end{itemize}
