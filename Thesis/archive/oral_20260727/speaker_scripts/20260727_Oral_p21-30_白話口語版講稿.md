# 20260727 Oral｜PDF p.21–30 白話口語版講稿

建議時間：約 6–8 分鐘。

這一版刻意少用專有名詞，適合口試現場自然講述。`【】`內是指圖提示，不需要念出來。

## PDF p.21｜Comparison Table

這張表主要想回答三件事：每個方法在什麼時候決定要不要查資料、它根據什麼做決定，以及這個決定我們看不看得懂。

FLARE 看得很細，會在 token 或句子層級看機率，但有時候某一個 token 機率低，只是用字或大小寫不同，不一定代表整個答案有問題。

Adaptive-RAG 是先看整題難不難，再選擇要不要 retrieval。它比較簡單，但 multi-hop 問題裡，通常不是整題都簡單或整題都困難，而是某些步驟需要查、某些步驟不需要。

DeepRAG 和我們一樣，會在 sub-question 層級決定。不過它的 decision policy 是訓練出來的，所以能力很強，但比較難直接看出它為什麼做這個決定。

SEEK 想取中間的平衡：在 sub-question 層級判斷，而且直接使用模型生成時本來就有的機率，讓決策比較容易說明。

**轉場：** 所以下一個問題就是，我們到底應該從這些機率裡看什麼？

## PDF p.22｜Methodology Overview

Methodology 有三部分：先找到信心訊號，再介紹 decomposer，最後說明兩條路徑怎麼推理和選答案。

現在先講第一部分，也就是我們怎麼從模型的機率，判斷一個回答可能不太可靠。

## PDF p.23｜Emphasizing the Tail Improves Error Detection

我們先做一個很單純的測試：同一組機率不變，只改變評分時比較重視前面的高機率 token，還是後面的低機率 token。

【指三張小圖】

alpha 等於 2 時，評分比較注意前面幾根高柱；一般 Shannon entropy 在中間；alpha 等於 0.5 時，後面那些小柱的影響會變大。

【指 AUROC】

結果從 0.651、0.671 提高到 0.716。也就是說，當我們更注意後面這些小機率 token 時，反而更容易把錯誤答案找出來。

這是我們開始看 tail 的第一個原因。不是因為最高機率完全沒用，而是錯誤可能先出現在後面：模型看起來有一個很高的答案，但同時也偷偷替很多其他答案保留了一些機率。

**轉場：** 不過，一般 entropy 不是本來就會看全部 token 嗎？下一頁就是回答這個問題。

## PDF p.24｜Same Entropy, Different Risk

Entropy 的確有看完整分布，問題不是它漏看了 tail，而是它最後只給我們一個總分。

【指兩邊 `PO` 與 `po`】

這裡兩邊最前面的答案完全一樣：`PO` 是 0.38，`po` 是 0.26。如果只看前兩名，我們會覺得模型的信心差不多；兩邊的 entropy 也可以相同。

【指藍色區域】

但是左邊只有 10% 的機率落在 top-5 之外，右邊卻有 20%。右邊等於替更多其他答案留了可能性，所以它對主要答案其實沒有那麼集中。

Entropy 會把「有多少機率跑到後面」和「跑到後面之後怎麼分」混在一起，因此不同情況最後可能得到同一個數字。

所以這裡真正想看的不是某一根小柱，而是後面全部小柱加起來，到底占了多少。

**轉場：** 為了把這件事說清楚，我們把整個機率分布切成前面和後面兩區。

## PDF p.25｜Separate Entropy into Head and Tail：先把分布切開

我們把機率最高的五個 token 叫做 head，排名第六之後全部叫做 tail。

`m_head` 就是前五名加起來的總機率。比如 `m_head` 是 0.9，就代表 90% 留在主要候選，另外 10% 在後面。

下面兩個公式只是把 head 和 tail 各自重新換算成 100%，方便我們分開看：前五名內部怎麼分，以及後面那些 token 內部怎麼分。

投影片上的 `mass` 可以直接理解成「加總後的總機率」，不用把它當成另一個新概念。

## PDF p.26｜Separate Entropy into Head and Tail：三種來源

把剛才的定義放回 entropy 之後，可以把同一個 entropy 拆成三塊。

【依序指紅、橘、藍線】

紅色問的是：有多少總機率留在前五名，又有多少跑到後面。

橘色問的是：前五名彼此競爭得多不多。像 `PO` 和 `po` 都很高，就會反映在這一塊。

藍色問的是：已經跑到後面之後，那些小機率 token 彼此怎麼分。

以前我們只看到一個 entropy 分數；現在拆開之後，就可以真的測試哪一塊和錯誤最有關。

**轉場：** 下一頁的實驗結果，正好告訴我們應該把注意力放在哪裡。

## PDF p.27｜Head/Tail Mass Is Most Predictive

【指三個數字】

第一個，也就是「有多少機率留在前五名、多少跑到後面」，AUROC 是 0.742，三者最高。

只看前五名內部怎麼競爭，是 0.712。只看 tail 裡面怎麼分，則只有 0.502，差不多等於亂猜。

這裡不是說 tail 不重要，而是要分成兩件事：第一件事是「跑出去多少」；第二件事是「跑出去以後怎麼分」。實驗顯示，真正和錯誤有關的是第一件事。

換句話說，我們不用記住後面每一個小 token，只要知道 top-5 還留住多少總機率，就已經抓到最重要的訊號。

**轉場：** 找到這個訊號後，我們就把它做成一個可以套用到整段答案的分數。

## PDF p.28｜Aggregating Leakage Across the Answer

模型每生成一個 token，都會重新產生一組機率。我們就在每一步看：前五名總共留住多少。

如果前五名留得少，代表有比較多機率跑到後面，我們就給這一步比較高的分數。

【指 `t1`、`t2`、`t3`】

一個答案可能不是某一個位置突然非常不確定，而是很多位置都各自有一點點不穩。如果只看最差的一步，這些小訊號可能會被忽略。

所以我們把每一步的分數加起來，變成整個答案的 Tail-Leakage Score。這些機率本來就是生成答案時算好的，所以不需要讓模型再跑一次，也不需要多訓練一個判斷器。

**轉場：** 接下來說明，為什麼每一步使用的是 `−log m_head`。

## PDF p.29｜Why Use `−log m_head`

我們需要的分數很直覺：越多機率跑到後面，分數就應該一路變高。

【指左圖】

左邊原本 entropy 形式的曲線會先上升、後下降。也就是說，當後面的機率已經非常多時，分數反而可能變小，方向不符合我們要的風險概念。

【指右圖】

右邊的 `−log m_head` 不會有這個問題。前五名留住的機率越少，它就一直往上升。因此高分永遠代表更多機率離開主要候選，方向很清楚。

而且使用 log 之後，每個 token 的分數可以直接相加，剛好適合前一頁的答案層級計分方式。

簡單來說，前面的 entropy 分解是幫我們找到「要看哪個數字」；這一頁則是在決定「要怎麼把這個數字變成風險分數」。

## PDF p.30｜Higher Tail Leakage Predicts More Errors

最後看這個分數和實際錯誤有沒有關係。

【由左往右指圖】

我們把四個資料集共 4,000 個答案，按照分數從低到高分成八組。綠色是答對，紅色是答錯。

最低分那組的錯誤率是 33%；分數越往右，錯誤率一路增加，最高分那組有 97% 答錯。

所以這張圖最重要的訊息很簡單：當更多機率離開主要候選，而且這個現象在答案中持續累積時，模型更容易答錯。

不過，這個分數不是保證。低分仍然可能答錯，高分也不是一定錯；它的功能是幫我們排序，找出哪些回答比較值得查資料或進一步檢查。

**收尾：** 整段方法的邏輯是：先發現後面的小機率值得注意，再確認關鍵不是它們怎麼排列，而是它們總共拿走多少機率；最後把這個現象累積成一個答案層級的分數。下一部分就會說明 SEEK 怎麼利用這個分數進行後續推理。
