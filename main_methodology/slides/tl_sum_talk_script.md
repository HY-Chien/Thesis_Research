## 封面：tl_sum——從 max_entropy 到尾漏 surprisal

老師好，今天要報告的是我們把 SEEK 的信心訊號從 max_entropy 換成一個新指標 tl_sum 的完整過程。

先講這份簡報的三個重點。第一，這個指標不是憑空設計出來的，它是從 42 個候選訊號的普查出發，再把 entropy 做數學分解之後，一步一步推出來的。第二，我會用四個資料集的證據說明它為什麼比 max_entropy、margin、log-probability 這些常見的信心指標都好。第三，我也會誠實地講它的極限在哪裡，哪些錯誤它抓不到。

實驗設定先講清楚：模型是 Llama-3-8B-Instruct，走 direct path，也就是完全不檢索、讓模型直接作答；資料集是 2WikiMultiHopQA、HotpotQA、MuSiQue、PopQA 四個，各取 1000 題；答案對錯的標籤用 alias-aware 的 Exact Match，意思是像「Poet」跟「poet」、或是維基百科上登記的別名，都算對。後面所有數字都是在這個設定下算的。

## 第 1 頁：gate 的任務——這一題,模型自己會嗎?

先說為什麼需要信心訊號。

SEEK 在處理每一個子問題的時候，要做一個二元決策：這一題模型自己會不會?如果判斷「會」，就讓模型直接作答，省下一次檢索；如果判斷「不會」，就送去檢索。這個決策我們叫它 gate。gate 能依據的唯一資訊，是模型作答當下的 token 機率分布——我們不做多次取樣，也不問第二個模型，因為那些都會增加成本，跟省檢索的目的矛盾。

原本的做法是 max_entropy：把答案裡每個 token 的 entropy 算出來，取最大的那一個，超過門檻 0.3 就送檢索。

這個訊號判錯的時候，有兩種具體的代價。第一種是誤報：這一題模型其實會，但訊號說不會，於是白白花了一次檢索，成本上升。第二種是漏報：這一題模型其實不會，但訊號說會，就直接放行了，答錯，準確率直接掉。所以一個好的信心訊號，就是要在同樣的檢索預算下，盡量把真正會錯的題挑出來。

那要改進 max_entropy，我們覺得不能只是換一個公式試試看，得先回答一個更根本的問題：entropy 到底在量什麼?它量的東西裡面，哪一部分真的跟答錯有關?這是整個研究的起點。

## 第 2 頁：兩種「不確定」長得不一樣——關鍵在機率的尾巴

這一頁是整份簡報最核心的觀察，我多花一點時間講。

模型每生成一個 token，其實是在整個詞表、大概 12 萬 8 千個詞上面，給出一個完整的機率分布。我們把候選詞按機率從高到低排序，機率最高的前 5 名叫「頭部」，第 6 名以後所有詞分到的機率總和，我們叫它「尾巴」——等一下 tl_sum 用的 top-5 mass，就是頭部這五名的機率總和。

【指上面第一條橫條圖】來看兩個從實驗資料裡抓出來的真實 token。第一個例子，題目問希臘詩人 Yannis Ritsos 的職業。答案第一個 token，模型給大寫開頭的「Po」51.7%，小寫的「po」45.6%。乍看之下這是五五波，非常不確定對不對?但仔細看，這兩個候選是同一個字的大小寫變體——不管選哪個，答案都是 Poet，都算對。更重要的是往後看：第 3 到第 5 名合計只有 2.7%，top-5 以外的尾巴只剩 0.1%。整個分布乾乾淨淨地被「同一個答案的兩種寫法」吸住了。這一題模型答對了。

【指下面第二條橫條圖】第二個例子，題目問演過 Corliss Archer 的那位女演員後來擔任什麼官職。第一個 token「First」有 55.8%——比剛才那題的 top-1 還高，看起來更有信心。但往後看就不對勁了：第二名以下碎成 Secretary、Ambassador、Congress、State 這些互不相干的猜測，而且有 27.3% 的機率——超過四分之一——漏到 top-5 以外的十二萬多個詞上面。模型最後答 First Lady，正確答案是 Chief of Protocol，答錯了。

所以這兩個 token 的 top-1 機率幾乎一樣，可是一個對、一個錯。差別不在頭部，在尾巴。

這背後的直覺是這樣：當模型真的知道答案的時候，不管這個答案有幾種寫法，機率都會被那幾種寫法牢牢吸住，尾巴是乾淨的。當模型不知道的時候，沒有任何一個候選吸得住機率，機率就會霧化、散到成千上萬個不相干的詞上。

【指下方四個數字方塊】答對率也完全順著這個形狀走。四個資料集合併四千題，整體 EM 是 24.1%。切開來看：每個 token 的 top-1 都大於等於 0.9、完全沒有競爭的題，EM 有 45.8%；top-5 裡面兩強相爭、但幾乎沒有尾漏的題，15.9%；top-5 內部平坦、也幾乎沒有尾漏的，14.6%；而只要尾漏超過 30%，EM 只剩 3.5%——尾巴一漏，幾乎必錯。

注意中間那兩格：頭部競爭很激烈,但只要尾巴乾淨，還有 15% 上下的答對率；尾巴一漏就掉到 3.5%。這說明「頭部競爭」跟「尾漏」是兩件不同的事，而真正致命的是後者。

## 第 3 頁：42 個訊號普查——越看尾巴的訊號，排名越前面

剛才那是觀察，接下來講我們怎麼系統性地驗證它。發現過程分三步，這是第一步。

我們先不預設任何答案，把文獻裡常見的信心訊號，總共 42 種，全部拿來對同一批 4×1000 題計算。這 42 種涵蓋了 entropy 家族、margin 家族、log-probability 家族、self-consistency、p(true) 這些主要的方法。

評估的指標是 AUROC。用白話解釋：隨機抽一題答錯的、一題答對的，看這個訊號有多大的機率把答錯那題排得比較「不確定」。0.5 就是亂猜，1.0 是完美。另外每個訊號都跟 max_entropy 做成對的 bootstrap 檢定，確認差距不是抽樣雜訊。

排行榜出來之後，浮現一個很一致的模式。最乾淨的證據是 Rényi entropy。它跟 Shannon entropy 是同一個家族，只多一個參數 α，控制小機率的「聲量」：α 等於 2 的時候，把每個機率平方，小機率平方之後趨近於零,所以尾巴消失，幾乎只看頭部；α 等於 0.5 的時候，把機率開根號，小機率開根號會變大，所以尾巴被放大。同一支公式，只轉這一個旋鈕，在 2wiki 上的結果是：α=2 只有 0.651，Shannon 是 0.671，α=0.5 到 0.716。**越往尾巴看，AUROC 越高，單調上升。**

其他訊號也全部同方向：直接量尾巴的 min_top5m 是 0.742、min_top10m 是 0.743，都排在前段班；只看頭部的訊號——top-1 機率 0.711、top-5 內部熵 0.712、margin 0.695——通通排在後面。

到這一步我們還不知道為什麼，但方向感已經很清楚了：**錯誤的訊號藏在分布的尾巴，不在頭部的排名競爭裡。**

## 第 4 頁：把 entropy 拆開——有判別力的只有「逃出 top-5」那一塊

第二步，我們要把「為什麼」講清楚。方法是把 Shannon entropy 做數學分解。

【指公式】H = [−m₅·log m₅ − (1−m₅)·log(1−m₅)] + m₅·H_top5 + (1−m₅)·H_tail

先把符號說清楚。模型在某一步給出的是全詞表上的分布，把機率由大到小排序，m₅ 就是前五名的機率總和，介於 0 和 1 之間；1−m₅ 就是前面一直在講的尾漏。

這個恆等式的來源，是把「生成一個 token」看成兩段式的抽樣。第一段，先擲一枚偏硬幣，決定這個 token 落在 top-5 之內還是之外——落在之內的機率就是 m₅。第二段，看硬幣的結果再抽具體是哪個詞：硬幣說在 top-5 之內，就照五個候選重新歸一化後的條件機率 pᵢ/m₅ 抽一個；說在之外，就照尾巴裡十二萬多個詞重新歸一化後的分布抽一個。兩段抽完，跟原本一步抽完的分布完全等價。

而 entropy 有一個很好的性質：抽樣拆成兩段的時候，總不確定性等於第一段的不確定性，加上兩個分支各自內部的不確定性、用走進該分支的機率加權。照這個性質展開，就得到公式右邊的三項。

第一個括號是 top-5／tail 的 mass-split 項。它只由 m₅ 一個數字決定，量的是「機率落在 top-5 還是 tail」這件事有多不確定，所以我們把它當成定位訊號的診斷項。這裡沒有新增模型參數；整個括號只是 entropy chain rule 自然產生的第一部分。

第二項 m₅·H_top5。H_top5 是 top-5 內部五個條件機率的 entropy：五個候選平分秋色它就大，一枝獨秀它就小。前面乘的 m₅ 是權重——只有真的走進 top-5 這個分支，內部怎麼分才有意義。這一項量的是頭部的猶豫，剛才 Po 對 po 那種寫法之爭，全部記在這一項。

第三項 (1−m₅)·H_tail。H_tail 是尾巴重新歸一化之後的 entropy，量的是漏出去的機率是攤在少數幾個詞上、還是霧化到幾萬個詞上；權重是逃出去的機率 1−m₅。

【停一下再強調】這是代數恆等式，不是近似——對每一個 token，三項加起來都精確等於原本的 Shannon entropy，一分不多一分不少。它的價值在於：既然 entropy 能無損地拆成三塊語意清楚的成分，我們就可以一塊一塊單獨拿去測 AUROC，看 entropy 的判別力到底藏在哪一塊——等於對一個公式做成分消融。

結果非常清楚【指表格】：escape 項單獨拿出來，macro AUROC 0.742；top-5 內部猶豫那一項，0.712，比較弱；尾巴內部組成那一項，0.502——就是亂猜，純雜訊。而三塊混在一起的 max_entropy 呢?0.726。

這就完整解釋了第一步看到的現象：max_entropy 的判別力，幾乎全部來自 escape 項。它混進來的另外兩塊，一塊比較弱而且跟 escape 項高度重疊，另一塊是純雜訊——混合的結果只會稀釋。所以把有效成分單獨拿出來，0.742，就已經贏過整支 entropy 的 0.726 了。

換句話說，max_entropy 不是不對，它是「對的訊號摻了水」。我們要做的就是把水濾掉。

## 第 5 頁：定義 tl_sum——把每一步的尾漏換成 surprisal，沿答案累加

第三步，正式定義新指標。

【指公式】tl_sum = Σₜ −log m₅⁽ᵗ⁾ = −log Πₜ m₅⁽ᵗ⁾

一個符號一個符號講。t 是答案裡 token 的編號，答案有幾個 token 就加幾項。m₅⁽ᵗ⁾ 是第 t 步的 top-5 機率總和——注意每一步的 top-5 是那一步自己排出來的前五名，不是固定一組詞——這個數字從 greedy decoding 本來就會算出的 logits 直接讀出來，不用重跑模型、不用多次取樣，零額外成本。

−log m₅⁽ᵗ⁾ 這個形式，在資訊理論裡叫 surprisal，量的是「這一步的 token 留在自己 top-5 之內」這個事件有多令人驚訝。m₅ 等於 1、一滴都沒漏的時候，−log 1 就是 0，完全不收費；漏得越多、m₅ 越小，收費越高。而且 −log 在 1 附近非常陡：top-5 合計 0.999 只收 0.001，合計 0.95 就收 0.051——後者已經超過錯題的中位數 0.0335，會被判成「不會」。這個陡峭是我們要的靈敏度，因為答對題的常態是幾乎零尾漏，中位數只有 0.0017。

第二個等號是對數的基本性質：負對數相加，等於乘積取負對數。Πₜm₅⁽ᵗ⁾ 是沿實際 greedy prefix 計算的 retained-mass path product；它不是生成答案本身的 joint likelihood。這個寫法的作用是讓每一步的 leakage 可以自然累積：任何一步漏一點，乘積就往下掉、tl_sum 就往上升，因此 token 級的量可以形成答案層級的風險分數。

【時間夠的話補充】這裡要把診斷和設計分開。Entropy decomposition 的實驗指出，最有判別力的是只依賴 m₅ 的 mass-split 項，因此我們找到的關鍵變數是 m₅；它不是直接把最終公式推導出來。接著，風險分數需要在 m₅ 越低時持續上升，但原本的 mass-split 項在 m₅=0.5 達到最高，之後反而下降，所以不適合描述單向 leakage severity。我們改用嚴格單調、而且能跨 token 相加的 retained-mass surprisal −log m₅。實測上，mass-split 診斷項取最大是 0.742，surprisal 沿答案加總是 0.749。第二，tl_sum 可以看成 log-probability 的寬容版：sum_lp 是對每一步收 −log p(選中的 token)，等於對「你選了哪個寫法」收費；tl_sum 把括號裡換成整包 top-5 的機率，所以 top-5 內部怎麼選一律免費，只對漏出包外的機率收費。選中的 token 一定在 top-5 裡，所以每一步 tl_sum 的收費都不會超過 sum_lp——它就是把 sum_lp 裡「寫法之爭」的罰款整筆退掉之後剩下的部分。

還有一個設計選擇要說明：為什麼是「加總」，而不是只看最差的那一步?我們把聚合方式都掃過一遍【指表格】：加總的 tl_sum 是 0.7493；只看最弱一步的 min_top5m 是 0.7419；取平均的 tl_mean 只有 0.7133，因為長答案裡大量乾淨的 token 會把訊號稀釋掉。tl_sum 對 min_top5m 的成對 bootstrap，p 小於 0.001，是統計上確實的差距。

sum 為什麼贏，原因在資料裡看得到：答錯的答案，傾向**每個 token 都漏一點**，而不是集中在單一 token 大漏。有一個量化證據：最弱的那個 token 佔整條答案 tl_sum 的比例，錯題是 0.88，答對題是 0.92——錯題的尾漏更分散在多個 token 上。只看單點的聚合方式看不到這種累積效應。所以答案越長，差距越大：7 個 token 以上的答案，tl_sum 的 AUROC 是 0.805，max_entropy 只有 0.787。

到這裡，指標的推導完成了：普查告訴我們訊號在尾巴，分解告訴我們有效成分是 escape 項，聚合掃描告訴我們要沿答案累加。tl_sum 就是這三個結論的乘積。

## 第 6 頁：主結果——對所有基線家族，每一格持平或更好

接下來是主結果。

【指點圖】這張圖是各家族代表訊號的 macro AUROC，四個資料集平均。tl_sum 0.749 排第一；它的單點版 min_top5m 0.742 第二；原本的基準 max_entropy 0.726，跟 log-prob 家族最強的 sum_lp 並列；再往下是 top-5 內部熵 0.712、min_lp 0.711、margin 家族最強的 min_margin 0.695、mean_lp 0.672。margin 跟 log-probability 家族都完整地包含在 42 訊號普查裡面，全數落後。

有一個常見的質疑是：會不會是某一個資料集特別有利,把平均拉上去的?【指下方表格】所以我們四個資料集逐一攤開來看：tl_sum 在 2wiki 是 0.717 對 max_entropy 的 0.671，贏了 4.6 個點；HotpotQA 0.757 對 0.743；MuSiQue 0.726 對 0.711；PopQA 0.798 對 0.780。**四個資料集、五個基線，每一格都是贏或持平，沒有任何一格輸。** 唯一持平的一格是 PopQA 上的 sum_lp,同樣是 0.798。對 max_entropy 的成對 bootstrap，p 小於 0.001。

另外一個重要的指標是 confident-wrong 率，就是「很有信心地答錯」——這是 gate 最危險的錯誤型態，因為這種題會被放行。以答對題的中位數當信心門檻，max_entropy 的 confident-wrong 率是 0.197，tl_sum 降到 0.157，下降大約兩成。

## 第 7 頁：操作點比較——同樣的預算，抓到更多錯題

AUROC 差 0.02 到底有多大?這一頁把它換算成 gate 實際操作上的意義。合併四千題來看。

第一種看法，固定要抓到的錯題比例：如果要求抓到 60% 的錯題，max_entropy 要冤枉 23.9% 的答對題陪著去檢索,tl_sum 只要 19.5%；要求抓到 80% 的錯題，max_entropy 冤枉 45.2%，tl_sum 是 39.9%。第二種看法，固定誤報率：同樣冤枉 30.6% 的答對題，max_entropy 抓到 67% 的錯題，tl_sum 抓到 71.6%。

整理成一句話：**在每一個預算水位上，tl_sum 都少冤枉 4 到 5 個百分點的答對題，或者多救回 4 到 5 個百分點的錯題。**

以上是離線的分類指標。我們也把 tl_sum 放回 gate 裡做端到端的重放實驗：讓 gate 跳過 10% 的檢索，用 tl_sum 挑哪些題跳過，macro EM 是 40.60，跟全部檢索的 40.58 完全持平——省了一成檢索，一分都沒掉；同樣跳過 10%，用 max_entropy 挑，EM 掉到 40.45。方向跟離線指標完全一致。

## 第 8 頁：機制解釋——只對「漏出候選集」收費

這一頁回答一個問題：tl_sum 為什麼會贏過 margin 跟 log-prob?我認為這是這個指標最漂亮的地方——它贏的原因可以講得非常清楚。

回到 Ritsos 那個 token：「Po」51.7%、「po」45.6%，top-5 合計 0.999。我們算給三個訊號看，它們各自跟這個 token 收多少「不確定費」。

margin 看的是第一名減第二名：0.517 減 0.456，只差 0.06，極小——margin 拉最高警報，把「猶豫寫法」當成最危險的形狀。log-prob 看的是選中那個 token 的機率：負 log 0.517，約 0.66——也是警報，它對「你選了哪一個寫法」收費。tl_sum 看的是 top-5 合計漏出去多少：負 log 0.999，約 0.001——安全。寫法怎麼選，它完全不收費，它只問一件事：機率漏出候選集多少。

這不是巧合，是設計上的對齊：我們的評分標準是 alias-aware EM，本來就不在乎答案寫成大寫 Poet 還是小寫 poet。**tl_sum 是這些訊號裡唯一把評分標準的這個寬容內建進去的**——它把 top-5 候選捆成一包，內部怎麼分完全不看，只量包外漏出的機率。margin 跟 log-prob 都對頭部的排名競爭收費,於是在大量無害的寫法之爭上白白付出誤報。

【時間夠的話補充；這段尺度特性若第 5 頁已經講過，可以跳過】這裡順便說明 tl_sum 的尺度特性,負對數在 1 附近非常敏感。答對題的 tl_sum 中位數只有 0.0017，對應每一步 top-5 質量都在 0.998 以上。你可能會覺得「top-5 合計 0.95」已經很接近滿分了，但負 log 0.95 是 0.051，已經超過錯題的中位數 0.0335——會被正確地判成「不會」。所以這個指標對「一點點尾漏」就有反應，這正是我們要的靈敏度。

## 第 9 頁：誠實的限制——盲區在哪裡

最後講限制。我們認為把邊界講清楚，跟把優勢講清楚一樣重要。

有一種形狀,tl_sum 確實無能為力：題目本身就列出兩個候選，模型知道答案必定是其中之一——所以尾巴「合法地」乾淨——只是選錯邊。

【指對照表】看這兩題的對比。左邊是 Ritsos 的職業：「Po」對「po」，0.52 比 0.46，top-5 合計 0.999，答對。右邊是「Aneta 跟 René 誰比較年輕」：「Ren」對「An」，0.56 比 0.44，top-5 合計 0.9997，答錯——因為它猶豫的是兩個不同的人，不是同一個答案的兩種寫法。

這兩題的機率**形狀**幾乎一模一樣，差別只在候選 token 的**內容**。所以任何只看分布形狀的訊號——max_entropy、margin、log-prob，也包括 tl_sum——都分不開這兩題。而且值得一提，max_entropy 給答對那題的分數甚至更高：不管門檻設在哪裡，都是兩題一起放行，或兩題一起送檢索。

這類「乾淨尾巴的真二選一」佔全部錯題大約 5%，189 題除以 4000，典型出現在 2wiki 的比較題。我要強調：這是所有分布形狀訊號的**共同上限**，不是 tl_sum 相對於基線的劣勢。

還有一個對照組數據支持我們的設計：頭部競爭是「同一個字的寫法變體」的題,有 53 題,EM 43.4%，跟完全沒有競爭的題差不多——證實寫法之爭確實無害，不應該為它付誤報費。margin 為這 53 題全部拉了警報，tl_sum 全部放行，放行是對的。

未來要救那 5%，需要「看內容」的訊號——比方把 top-2 候選解碼出來做字串比對，判斷它們是不是同一個答案的變體；或是對比較題型做特判。這是明確的後續方向。

## 第 10 頁：總結——三句話帶走

最後用三句話總結。

第一，**指標不是憑空設計的**。42 個訊號的普查指出訊號在尾巴；entropy 的恆等式分解證明它的判別力只來自 escape 項，其餘是稀釋；把有效成分換成 surprisal 沿答案累加，就得到 tl_sum。每一步都有前一步的證據支撐。

第二，**證據是成體系的**。成分消融、四個資料集全勝的 AUROC——0.749 對 0.726，p 小於 0.001——confident-wrong 率下降兩成、固定預算下多抓 4 到 5 個百分點的錯題、端到端重放省一成檢索 EM 不掉。五條獨立的證據，全部指向同一個方向。

第三，**邊界說得清楚**。它贏在不為無法判別的形狀付誤報費——寫法之爭一律寬容；代價是大約 5% 的乾淨尾巴真二選一看不到。而這是所有分布形狀訊號的共同上限，要突破它需要看內容的訊號，那是下一步的工作。

以上是今天的報告，請老師指教。

## 附錄：可能被問的問題與回答要點

**Q1：top-5 的 5 是怎麼選的?會不會太武斷?**
是超參數，但不敏感。掃描過 L=2、5、10：min_top2m 0.733、min_top5m 0.7419、min_top10m 0.7432，5 跟 10 幾乎相同，2 明顯較差。選 5 是在「涵蓋合理的寫法變體」跟「不把錯誤候選也包進來」之間的平衡點。換模型或 tokenizer 後值得重掃，但預期結論不變。

**Q2：為什麼不直接用 min_top5m 就好，還要做 sum?**
min_top5m 已經很強（0.7419），但它只看最弱一步。資料顯示錯題的尾漏是分散在多個 token 上的——最弱 token 只佔錯題 tl_sum 的 0.88，答對題是 0.92。sum 能累積這種分散的證據，成對 bootstrap p<0.001，而且答案越長優勢越大（7+ token：0.805 對 min 的 0.788）。

**Q3：這個結論會不會只在 Llama-3-8B 成立?**
誠實的回答是目前只在這一個模型、direct path 上驗證。但兩個理由讓我們認為方向可遷移：一是機制層面的——「知道就吸住、不知道就霧化」是 softmax 語言模型的普遍行為，不是 Llama 特有；二是四個性質很不同的資料集（多跳、比較題、單跳長尾）方向完全一致。操作點的門檻換模型當然要重新標定。

**Q4：跟 semantic entropy、p(true) 這些方法比呢?**
都在 42 訊號普查裡。semantic entropy 系列在 2wiki 約 0.657–0.659，p(true) 帶上下文只有 0.567，都明顯落後。而且它們要多次取樣或多跑一次前向，成本更高；tl_sum 從一次 greedy decoding 的 logits 就能算，零額外成本。

**Q5：confident-wrong 還剩下的那些是什麼?**
491 題人工分類：最大宗是參數化幻覺 281 題——模型「記錯了」而且記得很確定，分布上跟答對無法區分，這是任何信心訊號的天花板，也正是檢索存在的理由；其次是別名邊界近似 148 題（如 Lush 對 Lush Ltd.），其實接近評分邊界問題；剩下是部分重疊 40 題、日期數字錯 22 題。

**Q6：門檻 τ 實務上怎麼設?**
tl_sum 的尺度高度非線性（答對題中位數 0.0017、錯題 0.0335），所以用 pooled quantile 設定——先決定要跳過多少比例的檢索，再取對應分位數當 τ。端到端重放顯示跳過 10% 是安全點（EM 40.60 對全檢索 40.58）,跳到 15% 開始小幅下滑（40.25）。
