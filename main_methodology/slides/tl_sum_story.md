# tl_sum 指標的前因後果（簡報底稿）

這份文件用文字把 tl_sum 的完整故事講一遍：為什麼要換掉 max_entropy、我們是怎麼一步一步找到 tl_sum 的、它比其他信心指標好在哪裡、以及它還有哪些做不到的事。每一節開頭有一句話結論，方便直接搬進投影片。

實驗設定（全文共用）：Llama-3-8B-Instruct，direct path（無檢索直接作答），2wiki / HotpotQA / MuSiQue / PopQA 各 1000 題，標籤為 alias-aware EM。

---

## 1. 問題設定：gate 為什麼需要一個好的信心訊號

**一句話：gate 的任務是判斷「這一題模型自己會不會」，判錯的兩種代價都很具體。**

SEEK 對每個子問題要做一個二元決策：如果模型自己就會，直接作答，省下一次檢索；如果不會，送去檢索。判斷的唯一依據是模型作答當下的 token 機率分布——沒有外部資訊，也不能重複取樣。

原本的訊號是 max_entropy：取答案中 entropy 最大的那個 token，超過門檻（τ=0.3）就送檢索。它判錯有兩種代價：

- **誤報**：會答對的題被判「不會」，白花一次檢索，成本上升；
- **漏報**：會答錯的題被判「會」而放行，直接損失答對率。

要換掉 max_entropy，得先回答一個問題：entropy 到底在量什麼？它量的東西裡，哪一部分真的和答錯有關？

## 2. 核心觀察：兩種「不確定」長得不一樣，關鍵在機率的尾巴

**一句話：模型知道答案時，機率被少數幾種寫法吸住、尾巴乾淨；不知道時，機率霧化到十幾萬個詞上——尾巴一漏，幾乎必錯。**

模型每生成一個 token，是在約 12.8 萬個詞上給一個完整分布。把候選按機率排序，「頭部」是機率最高的前 5 名，「尾巴」是第 6 名以後所有詞分到的機率總和（即 1 − top-5 mass，與 tl_sum 實際使用的切分一致）。從實驗資料裡抓兩個 token，top-1 機率幾乎相同，命運卻相反：

**案例一（答對）**：問 Yannis Ritsos 的職業，答案第一個 token 是 `Po`（0.517）對 `po`（0.456）——競爭全部集中在同一個字的大小寫變體上，top-5 以外的尾巴只有 0.1%。模型知道答案是 Poet，只是猶豫寫法。

**案例二（答錯）**：問 Corliss Archer 那位演員的官職，第一個 token `First`（0.558）看起來很有信心，但 top-2 以下碎成 Secretary、Ambassador、Congress、State 等互不相干的猜測，還有 27.3% 的機率漏出 top-5，霧化到十二萬多個詞上。模型預測 First Lady，正解是 Chief of Protocol。

答對率順著這個形狀走（四資料集合併 n=4000，整體 EM 24.1%）：

| 機率形狀 | EM | n |
|---|---:|---:|
| 每個 token top-1 ≥ 0.9（毫無競爭） | 45.8% | 1142 |
| top-5 內兩強相爭（幾乎無尾漏） | 15.9% | 586 |
| top-5 內平坦（幾乎無尾漏） | 14.6% | 212 |
| 尾漏 ≥ 30%（min top5m ≤ 0.7） | 3.5% | 346 |

## 3. 發現過程第一步：42 個訊號普查，方向指向尾巴

**一句話：不預設答案把文獻裡的信心訊號全部測一遍，排行榜浮現一致的模式——越看尾巴的訊號，排名越前面。**

我們把文獻裡常見的信心訊號共 42 種（entropy 家族、margin、log-prob、self-consistency、p(true) 等）全部對同一批 4×1000 題計算 AUROC——隨機抽一題答錯、一題答對，訊號把答錯那題排得更不確定的機率，0.5 是亂猜、1.0 是完美——並對 max_ent 做成對 bootstrap 檢定。

最乾淨的證據是 Rényi entropy。它與 Shannon 同一家族，只多一個參數 α 控制小機率的聲量：α=2 把機率平方，尾巴消失，只看頭部；α=0.5 把機率開根號，尾巴被放大。同一支公式只轉這個旋鈕，在 2wiki 上：

| 公式 | 看哪裡 | AUROC（2wiki） |
|---|---|---:|
| Rényi α=2 | 幾乎只看前一兩名 | 0.651 |
| Shannon（= max_ent） | 頭尾各算各的 | 0.671 |
| Rényi α=0.5 | 放大尾巴 | **0.716** |

其他訊號同方向：直接量尾巴的 min_top5m（macro 0.742）、min_top10m（0.743）排在前段；只看頭部的 top-1 機率（0.711）、top-5 內部熵（0.712）、margin（0.695）排在後段。

這一步還不知道為什麼，只得到方向感：**錯誤的訊號藏在分布的尾巴，不在頭部的排名競爭裡。**

## 4. 發現過程第二步：把 entropy 拆開，有判別力的只有一塊

**一句話：Shannon entropy 可以恆等式分解成三塊，逐塊測 AUROC 之後發現，判別力幾乎全部來自「機率有沒有逃出 top-5」那一塊，其餘是稀釋。**

Shannon entropy 有一個 chain-rule 恆等式分解（m₅ 為 top-5 機率總和）：

```
H = H_B(m₅) + m₅·H_top5 + (1−m₅)·H_tail
```

三塊各有明確語意，而且可以分開計算、分開測 AUROC（macro，四資料集平均）：

| 成分 | 語意 | macro AUROC |
|---|---|---:|
| H_B(m₅)（escape 項） | 機率有沒有逃出 top-5 | **0.742** |
| m₅·H_top5 | top-5 內部的猶豫 | 0.712 |
| (1−m₅)·H_tail | 尾巴內部的組成 | 0.502（≈亂猜） |
| max_ent（三塊混合） | | 0.726 |

這解釋了第一步的現象：max_ent 的判別力幾乎全部來自 escape 項；它混進來的另外兩塊，一塊較弱且與 escape 項重疊，一塊是純雜訊——混合只會稀釋。把有效成分單獨拿出來（0.742），就已經勝過整支 entropy（0.726）。

## 5. 發現過程第三步：定義 tl_sum

**一句話：把每一步的尾漏換成 surprisal、沿整條答案累加，就是 tl_sum；聚合方式掃描顯示 sum 顯著勝過只看最弱一步。**

```
tl_sum = Σₜ −log m₅⁽ᵗ⁾ = −log Πₜ m₅⁽ᵗ⁾
```

它的語意是「整條答案的每一步都留在自己 top-5 候選集內」的聯合機率取負對數——任何一步漏一點,乘積就往下掉。確定訊號是尾漏之後，我們掃描了聚合方式（完整表在 `results/reports/tail_leakage_variants.md`）：

| 聚合方式 | 直覺 | macro AUROC |
|---|---|---:|
| tl_sum（累加） | 沿整條答案累積尾漏 | **0.7493** |
| min_top5m（最弱一步） | 只看漏最多的 token | 0.7419 |
| tl_mean（平均） | 被長答案的乾淨 token 稀釋 | 0.7133 |

tl_sum 對 min_top5m 的成對 bootstrap p<0.001。sum 贏的原因在資料裡看得到：答錯的答案傾向**每個 token 都漏一點**——最弱 token 只佔錯題 tl_sum 的 0.88（答對題 0.92），單點聚合看不到這種累積。答案越長差距越大：7 個 token 以上的答案，tl_sum 0.805 對 max_ent 0.787。

## 6. 主結果：對所有基線家族，四個資料集逐一全勝或持平

**一句話：macro AUROC 0.749 對 max_ent 的 0.726（p<0.001），而且不是靠某個資料集拉分——每個資料集、每個基線都贏或持平。**

| 訊號 | 2wiki | HotpotQA | MuSiQue | PopQA | macro |
|---|---:|---:|---:|---:|---:|
| **tl_sum** | **0.717** | **0.757** | **0.726** | **0.798** | **0.749** |
| max_ent（原基準） | 0.671 | 0.743 | 0.711 | 0.780 | 0.726 |
| sum_lp | 0.667 | 0.733 | 0.707 | 0.798 | 0.726 |
| min_lp | 0.641 | 0.724 | 0.699 | 0.778 | 0.711 |
| min_margin | 0.622 | 0.708 | 0.680 | 0.771 | 0.695 |
| mean_lp | 0.604 | 0.697 | 0.667 | 0.722 | 0.672 |

margin 與 log-probability 家族也都在 42 訊號普查內，全數落後。最危險的錯誤型態「很有信心地答錯」（confident-wrong at median，CW@med）也從 max_ent 的 0.197 降到 0.157，下降約兩成。

## 7. 操作點比較：同樣的預算，抓到更多錯題

**一句話：AUROC 的差距換算到 gate 的實際操作點上，每個預算水位都少冤枉 4–5 個百分點的答對題，或多救回 4–5 個百分點的錯題；端到端重放也一致。**

pooled n=4000：

| 固定條件 | max_ent | tl_sum |
|---|---:|---:|
| 要抓到 60% 的錯題時，誤報的答對題 | 23.9% | **19.5%** |
| 要抓到 80% 的錯題時，誤報的答對題 | 45.2% | **39.9%** |
| 同樣誤報 30.6% 時，抓到的錯題 | 67.0% | **71.6%** |

放回 gate 做端到端重放（`results/reports/step_gate_signal_sweep.md`）：跳過 10% 的檢索時，tl_sum 的 macro EM 40.60，與全檢索的 40.58 持平；max_ent 同樣跳過率降到 40.45。也就是說用 tl_sum 當訊號，可以省一成檢索而完全不掉分。

## 8. 機制解釋：為什麼贏過 margin 與 log-prob

**一句話：tl_sum 是唯一把評分標準的寬容內建進去的訊號——top-5 內部怎麼分完全不看，只對「漏出候選集」收費，所以不會在無害的寫法之爭上付誤報。**

用 Ritsos 那個 token（`Po` 0.517 / `po` 0.456，top-5 合計 0.999）算給三個訊號看：

| 訊號 | 對這個 token 收多少「不確定費」 | 判斷 |
|---|---|---|
| margin | 0.517−0.456 = 0.06，極小 | 高度警報——把猶豫寫法當成最危險的形狀 |
| sum_lp | −log 0.517 ≈ 0.66 | 警報——對「選了哪個寫法」收費 |
| **tl_sum** | −log 0.999 ≈ 0.001 | 安全——寫法怎麼選不收費，只問漏出多少 |

這不是巧合而是設計：評分標準（alias-aware EM）本來就不在乎答案寫成 Poet 還是 poet。margin 和 log-prob 都對頭部的排名競爭收費，於是在大量無害的寫法之爭上付出誤報。對照證據：頭部競爭是同字寫法變體的題（n=53），EM 43.4%，與毫無競爭的題相當——寫法之爭確實無害，不該為它付誤報費。

一個尺度上的細節：−log 在 1 附近極敏感。答對題的 tl_sum 中位數只有 0.0017，對應每步 top-5 質量 0.998 以上；「top-5 合起來 0.95」看似接近滿分，其實 −log 0.95 = 0.051，已超過錯題中位數 0.0335，會被正確地判為「不會」。

## 9. 限制與後續可能遇到的問題

**一句話：tl_sum 的邊界說得清楚——約 5% 的錯題是所有分布形狀訊號的共同盲區；此外殘差裡最大宗是「乾淨地答錯」的參數化幻覺，這類問題任何信心訊號都救不了，只能靠檢索。**

### 9.1 盲區：尾巴乾淨的真二選一

有一種形狀 tl_sum 確實無能為力：題目本身列出兩個候選、模型知道答案必是其一（所以尾巴合法地乾淨），只是選錯邊。兩個真實例子，機率形狀幾乎相同、命運相反：

| | Ritsos 的職業 | Aneta 與 René 誰年輕 |
|---|---|---|
| 頭部競爭 | `Po` 0.52 vs `po` 0.46 | `Ren` 0.56 vs `An` 0.44 |
| top-5 合計 | 0.999 | 0.9997 |
| tl_sum | 0.001 | 0.0003 |
| 結果 | 答對（猶豫的是同一答案的寫法） | **答錯**（猶豫的是兩個不同的人） |

差別只在候選 token 的**內容**，不在機率的**形狀**——所以任何只看分布形狀的訊號（max_ent、margin、log-prob、tl_sum）都分不開這兩題。max_ent 給答對那題的分數甚至更高，任何門檻都是兩題一起放行或一起送檢索。這類題佔全部錯題約 5%（189/4000，典型是 2wiki 比較題），是分布形狀訊號的共同上限，不是 tl_sum 相對於基線的劣勢。要救這 5%，需要看內容的訊號——解碼 top-2 候選做字串比對，或對比較題型特判。

### 9.2 殘差：confident-wrong 的組成

即使用了 tl_sum，仍有一批「很有信心地答錯」的題（tl_sum ≤ 答對題中位數的錯題，共 491 題）。人工分類後的組成（`results/reports/tlsum_confidence_story.md`）：

| 類別 | 題數 | 說明 |
|---|---:|---|
| 參數化幻覺（乾淨地答出錯的實體） | 281 | 模型「記錯了」，分布上與答對無法區分 |
| 邊界／別名近似（Lush vs Lush Ltd.） | 148 | 其實答案接近正確，是評分邊界問題 |
| 部分重疊（混合實體） | 40 | |
| 日期／數字錯誤 | 22 | |

最大宗的參數化幻覺對任何信心訊號都是天花板：模型自己不知道自己記錯了。這正是檢索存在的理由——gate 的目標不是消滅這類錯誤，而是在不放過它們的前提下省掉不必要的檢索。

### 9.3 反方向的殘差：unconfident-right

答對卻被判「不會」的題有 164 題（佔答對題 17%）。特徵是答案偏短（平均 2.5 token 對全體答對題的 3.2），內容多為模型其實知道、但輸出時有多種同義表達的情況。這部分是白花的檢索成本，但不損失答對率。

### 9.4 部署時要注意的事

- **門檻在 log 空間才線性**：tl_sum 的尺度高度非線性（答對題中位數 0.0017、錯題 0.0335），調 τ 時用 pooled quantile 或 log 空間掃描，不要在原始尺度上等距掃。
- **候選集大小 L=5 是超參數**：目前 L=5 與 L=10 表現幾乎相同（0.7493 vs min_top10m 0.7432），但換 tokenizer 或換模型後值得重掃一次。
- **目前只在一個模型、一條路徑上驗證**：所有數字都來自 Llama-3-8B-Instruct 的 direct path。換模型（尤其是校準特性不同的模型）、換成 CoT 路徑、或換標籤定義（F1 而非 EM）時，結論方向預期不變，但操作點數字要重新標定。
- **與檢索後的信心是兩回事**：tl_sum 量的是「模型自己會不會」，檢索之後的作答信心是另一個分布，不能直接沿用同一個門檻。

## 10. 總結

1. **指標不是憑空設計的**：42 訊號普查指出「訊號在尾巴」，entropy 的恆等式分解證明它的判別力只來自 escape 項，其餘是稀釋；把有效成分換成 surprisal 沿答案累加，就是 tl_sum。
2. **證據是成體系的**：成分消融、四資料集全勝的 AUROC（0.749 vs 0.726，p<0.001）、confident-wrong 率下降兩成、固定預算下多抓 4–5 個百分點錯題、端到端 gate 重放跳過 10% 檢索 EM 不掉——五條獨立證據同向。
3. **邊界說得清楚**：它贏在不為「無法判別的形狀」付誤報費——寫法之爭一律寬容；代價是約 5% 的乾淨尾巴真二選一看不到，而這是所有分布形狀訊號的共同上限，需要看內容的訊號才能突破。
