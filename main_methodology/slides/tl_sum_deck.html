SEEK 信心訊號 · 進度報告

tl_sum：從 max_entropy 到尾漏 surprisal

gate 需要判斷「這一題模型自己會不會」。這份簡報說明我們如何從 42 個候選訊號的普查出發，把 entropy 拆解後找出真正有判別力的成分，得到新的指標 tl_sum，並以四個資料集的證據說明它為什麼優於 max_entropy、margin 與 log-probability。

1 · 問題設定

gate 的任務：這一題，模型自己會嗎？

系統對每個子問題要做一個二元決策：判「會」就直接作答、省下一次檢索；判「不會」就送去檢索。判斷的依據是模型作答當下的 token 機率分布。

原本的訊號是 max_entropy：取答案中 entropy 最大的那個 token，超過門檻（τ=0.3）就檢索。它有兩種代價：

  • 誤報——會答對的題被判「不會」，白花一次檢索；
  • 漏報——答錯的題被判「會」而放行，直接損失答對率。

要換掉它，得先回答：entropy 到底在量什麼？它量的東西裡，哪一部分真的和答錯有關？

2 · 核心觀察

3 · 發現過程 · 第一步

42 個訊號普查：越看尾巴的訊號，排名越前面

我們先不預設答案，把文獻裡常見的信心訊號共 42 種（entropy 家族、margin、log-prob、self-consistency、p(true) 等）全部對同一批 4×1000 題計算 AUROC——即隨機抽一題答錯、一題答對，訊號把答錯那題排得更不確定的機率，0.5 是亂猜、1.0 是完美——並對 max_ent 做成對 bootstrap 檢定。

排行榜浮現一個一致的模式。最乾淨的版本是 Rényi entropy：它與 Shannon 同家族，只多一個參數 α 控制小機率的聲量——α=2 把機率平方，尾巴消失，只看頭；α=0.5 把機率開根號，尾巴被放大。同一支公式只轉這個旋鈕，在 2wiki 上：

公式看哪裡AUROC（2wiki）
Rényi α=2幾乎只看前一兩名0.651
Shannon（= max_ent）頭尾各算各的0.671
Rényi α=0.5放大尾巴0.716

其他訊號同方向：量尾巴的 min_top5m（0.742）、min_top10m（0.743）排前段；只看頭部的 top-1 機率（0.711）、top-5 內部熵（0.712）、margin（0.695）排後段。

這一步還不知道為什麼，只得到方向感：錯誤的訊號藏在分布的尾巴，不在頭部的排名競爭裡。

4 · 發現過程 · 第二步

把 entropy 拆開：有判別力的只有「逃出 top-5」那一塊

Shannon entropy 有一個恆等式分解（m₅ 為 top-5 機率總和）：

H = HB(m₅) + m₅·Htop5 + (1−m₅)·Htail

三塊各有明確語意，而且可以分開計算、分開測 AUROC：

成分語意macro AUROC
HB(m₅)（escape 項）機率有沒有逃出 top-50.742
m₅·Htop5top-5 內部的猶豫0.712
(1−m₅)·Htail尾巴內部的組成0.502（≈亂猜）
max_ent（三塊混合）0.726

這解釋了第一步的現象：max_ent 的判別力幾乎全部來自 escape 項；它混進來的另外兩塊，一塊較弱且與 escape 項重疊，一塊是純雜訊——混合只會稀釋。把有效成分單獨拿出來（0.742），就已經勝過整支 entropy（0.726）。

5 · 發現過程 · 第三步

定義 tl_sum：把每一步的尾漏換成 surprisal，沿答案累加

tl_sum = Σt −log m₅(t) = −log Πt m₅(t)

它是「整條答案的每一步都留在自己 top-5 候選集內」的聯合機率取負對數——任何一步漏一點，乘積就往下掉。確定訊號是尾漏之後，我們掃描了聚合方式，sum 顯著勝出（對 min_top5m 的成對 bootstrap p<0.001）：

聚合方式直覺macro AUROC
tl_sum（累加）沿整條答案累積尾漏0.7493
min_top5m（最弱一步）只看漏最多的 token0.7419
tl_mean（平均）被長答案的乾淨 token 稀釋0.7133

sum 贏的原因在資料裡看得到：答錯的答案傾向每個 token 都漏一點——最弱 token 只佔錯題 tl_sum 的 0.88（答對題 0.92），單點聚合看不到這種累積。答案越長差距越大：7 個 token 以上的答案，tl_sum 0.805 對 max_ent 0.787。

7 · 操作點比較

對 gate 的實際意義：同樣的預算，抓到更多錯題

AUROC 的差距換算到 gate 的操作點上（pooled n=4000）：

固定條件max_enttl_sum
要抓到 60% 的錯題時，誤報的答對題23.9%19.5%
要抓到 80% 的錯題時，誤報的答對題45.2%39.9%
同樣誤報 30.6% 時，抓到的錯題67.0%71.6%

每一個預算水位上，tl_sum 都少冤枉 4–5 個百分點的答對題，或多救回 4–5 個百分點的錯題。放回 gate 做端到端重放也一致：跳過 10% 的檢索時，tl_sum 的 macro EM 40.60，與全檢索的 40.58 持平；max_ent 同樣跳過率降到 40.45。

8 · 機制解釋

為什麼贏過 margin 與 log-prob：只對「漏出候選集」收費

用 Ritsos 那個 token（Po 0.517 / po 0.456，top-5 合計 0.999）算給三個訊號看：

訊號它跟這個 token 收多少「不確定費」判斷
margin0.517−0.456 = 0.06，極小高度警報——把猶豫寫法當成最危險的形狀
sum_lp−log 0.517 ≈ 0.66警報——對「選了哪個寫法」收費
tl_sum−log 0.999 ≈ 0.001安全——寫法怎麼選不收費，只問漏出多少

這不是巧合而是設計：評分標準（alias-aware EM）本來就不在乎答案寫成 Poet 還是 poet，tl_sum 是唯一把這個寬容內建進去的訊號——top-5 內部怎麼分完全不看，把五個候選捆成一包，只量包外漏出的機率。margin 和 log-prob 都對頭部的排名競爭收費，於是在大量無害的寫法之爭上付出誤報。

注意 tl_sum 的尺度：−log 在 1 附近極敏感。答對題的 tl_sum 中位數只有 0.0017，對應每步 top-5 質量 0.998 以上；「top-5 合起來 0.95」看似接近滿分，其實 −log 0.95 = 0.051，已超過錯題中位數 0.0335——會被正確地判為「不會」。

9 · 誠實的限制

盲區：尾巴乾淨的真二選一——但誰都看不到

有一種形狀 tl_sum 確實無能為力：題目本身列出兩個候選、模型知道答案必是其一（所以尾巴合法地乾淨），只是選錯邊。兩個真實例子，機率形狀幾乎相同、命運相反：

Ritsos 的職業Aneta 與 René 誰年輕

top-5 合計0.9990.9997

結果答對（猶豫的是同一答案的寫法）答錯（猶豫的是兩個不同的人）

差別只在候選 token 的內容，不在機率的形狀——所以任何只看分布形狀的訊號（max_ent、margin、log-prob、tl_sum）都分不開這兩題。max_ent 給答對那題的分數甚至更高，任何門檻都是兩題一起放行或一起送檢索。

  • 這類「乾淨尾巴的真二選一」佔全部錯題約 5%（n=189/4000，典型是 2wiki 比較題），是分布形狀訊號的共同上限，不是 tl_sum 相對於基線的劣勢。
  • 對照組：頭部競爭是同字寫法變體的題（n=53），EM 43.4%，與毫無競爭的題相當——證實寫法之爭確實無害，不該為它付誤報。
  • 未來方向：要救這 5%，需要看內容的訊號——解碼 top-2 候選做字串比對，或對比較題型特判。
10 · 總結

三句話帶走

  1. 指標不是憑空設計的：42 訊號普查指出「訊號在尾巴」，entropy 的恆等式分解證明它的判別力只來自 escape 項，其餘是稀釋；把有效成分換成 surprisal 沿答案累加，就是 tl_sum。
  2. 證據是成體系的：成分消融、四資料集全勝的 AUROC（0.749 vs 0.726，p<0.001）、confident-wrong 率下降兩成、固定預算下多抓 4–5 個百分點錯題、端到端 gate 重放跳過 10% 檢索 EM 不掉——五條獨立證據同向。
  3. 邊界說得清楚：它贏在不為「無法判別的形狀」付誤報費——寫法之爭一律寬容；代價是約 5% 的乾淨尾巴真二選一看不到，而這是所有分布形狀訊號的共同上限，需要看內容的訊號才能突破。
